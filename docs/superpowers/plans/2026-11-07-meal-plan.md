# Kochplan (Teil 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Gruppen-Kochpläne (Woche, Einträge je Tag), Tage einkaufen mit Vorschau, Entfernen mit Abziehen von der Liste.

**Architecture:** Neues Paket `internal/mealplan` (Dateien in Git, wie `internal/tasks`). `internal/shopping` bekommt `Remove`. `internal/web` bekommt `/mealplan…`, `/recipes/{id}/plan`, `/admin/mealplans`.

**Spec:** `docs/superpowers/specs/2026-11-07-meal-plan-design.md`

## Global Constraints

SPDX-Kopf; keine neue Abhängigkeit; Funktionen ~30 Zeilen, zyklomatisch ≤ 10; TDD; Doku im selben Commit; Branch `mealplan`. Nur Mitglieder der Gruppe sehen/ändern einen Plan (Admins nicht automatisch). Abziehen ändert nie einen abgehakten Eintrag.

## Review Focus

1. Abziehen bei mehreren Herkünften: nur den eigenen Anteil, Eintrag bleibt mit den anderen – Task 2.
2. Abziehen eines Eintrags, dessen Text die Person seither geändert hat (Menge unverträglich) – nur Herkunft weg – Task 2.
3. Zwei Gerichte desselben Rezepts in einer Woche: zwei Fill-IDs, zwei Herkünfte, Abziehen nimmt nur einen – Task 4.
4. Woche-Parameter ungültig (`2026-W99`, `abc`) → aktuelle Woche, kein Fehler – Task 3.
5. Rezept im Plan, das die Person nicht lesen darf: Titel ohne Link, beim Einkaufen übersprungen – Task 4.

### Task 1: `internal/mealplan`

**Produces:**
```go
type Plan struct { ID string `yaml:"-"`; Name string; Group string; Created time.Time }
type Entry struct { ID, Recipe, Title string; Servings int; Fill, List string `yaml:",omitempty"` }
type Week struct { Key string `yaml:"-"`; Days map[string][]Entry `yaml:"days"` } // Tag "2006-01-02"
func NewStore(dataDir string, repo *store.Repo) *Store
func (s *Store) Create(a store.Author, name, group string) (Plan, error)
func (s *Store) Delete(a store.Author, id string) error
func (s *Store) All() []Plan                                   // nach Name
func (s *Store) For(groups access.Groups, sub string) []Plan   // Pläne der Gruppen von sub
func (s *Store) Get(groups access.Groups, sub, id string) (Plan, error) // ErrNotFound für Nichtmitglieder
func (s *Store) Week(planID, key string) (Week, error)          // fehlende Datei = leere Woche
func (s *Store) Update(a store.Author, planID, key string, fn func(*Week) error) error // unter Repo-Sperre, Commit
func WeekKey(t time.Time) string                               // ISO "2026-W46"
func ParseWeek(key string, now time.Time) (start time.Time, canonical string) // ungültig → aktuelle Woche
func Days(start time.Time) []time.Time                          // Mo..So
```
Tests: Create/All/For/Get-Rechte; Update legt Datei an und committet; ParseWeek (gültig, `2026-W99`, `abc`, Jahreswechsel 2026-W53 → 2027-W53 existiert nicht → aktuelle); Days.

### Task 2: `shopping.Remove`

`func Remove(list *todos.List, fill string, lang string, now time.Time) int` – je Eintrag mit Herkunft `fill`: abgehakt → unverändert; einzige Herkunft → löschen (Tombstone in `list.Deleted`); sonst Menge um `Source.Amount` verringern, wenn verträglich (Ergebnis ≤ 0 → löschen), Herkunft entfernen. Zählt geänderte Einträge.
Tests: einzige Herkunft → weg; zwei Herkünfte 700 g → 200 g; Text geändert auf „2 Pck. Mehl“ → nur Herkunft weg; abgehakt → unverändert; Herkunft ohne Menge → nur Herkunft weg.

### Task 3: Wochenansicht, Hinzufügen, Entfernen (ohne Abziehen), Admin, Küche-Reiter, Einplanen

Routen: `GET /mealplan` (→ erster Plan oder Hinweis), `GET /mealplan/{plan}?week=`, `GET/POST /mealplan/{plan}/add?day=`, `POST /mealplan/{plan}/remove` (entry, week), `GET/POST /recipes/{id}/plan`, `GET/POST /admin/mealplans`.
Tests: Nichtmitglied 404; Woche zeigt Einträge mit Link nur bei lesbarem Rezept; Hinzufügen mit vorbelegten Portionen; Einplanen von der Rezeptseite; ungültige Woche; Admin anlegen/löschen; Reiter in Küche.

### Task 4: Tage einkaufen, Entfernen mit Abziehen

Routen: `GET/POST /mealplan/{plan}/shop?week=&day=…` (Vorschau je Gericht; Takes `e<n>-<i>`; Fill je Eintrag `fill-<entry>`; refresh wie beim Rezept), `GET/POST /mealplan/{plan}/remove?entry=` mit Bestätigung, wenn `fill` gesetzt.
Tests: zwei Tage → Abschnitte, Summe über Gerichte; Übernehmen setzt `fill`/`list`; schon eingekauft nicht angeboten; doppeltes POST einmal; Entfernen mit Abziehen und „nur aus dem Plan“; nicht lesbares Rezept übersprungen.
