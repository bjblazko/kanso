# Berichte (reports) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Berichte" page in the user menu with seven tabs and 14 d3 charts about documents, storage, activity, wiki, tasks, kitchen and sharing, scoped per viewer, with per-person numbers for admins.

**Architecture:** `internal/store` gains one Git history scan; a new pure package `internal/reports` turns plain inputs (documents, events, scan) into chart data; `internal/web` collects the inputs per viewer and scope, caches the Git part per HEAD, renders a table per chart plus the same data as JSON; `web/static/js/reports.js` draws the charts with vendored d3.

**Tech Stack:** Go stdlib, html/template, Git CLI, d3 7.9.0 (vendored, ISC), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-reports-design.md`

## Global Constraints

- Every source file starts with `// SPDX-License-Identifier: Apache-2.0` (JS: same comment; HTML templates: none, as today).
- Git is called as a program with an argument list via `store.Repo` (never a shell).
- No CDN, no telemetry, nothing new leaves the machine; no new cookies or storage.
- Functions ~30 lines, cyclomatic ≤ 10; packages by domain.
- d3: exactly `d3.min.js` 7.9.0 at `web/static/vendor/d3/d3.min.js`, license text `web/static/licenses/d3.txt`, entry in `web/static/licenses/index.yaml`; loaded only on report pages.
- Chart colours: `--chart-1…6` light `#2a78d6 #1baf7a #eda100 #e87ba4 #008300 #6250d6`, dark `#3987e5 #199e70 #c98500 #d55181 #0ca30c #9085e9`; one series = `--chart-1`, no legend; sequential = `--bg-2` → `--chart-1`; "gelöscht" = hatch. No orange in charts.
- Admins see titles, file names and links only for things they may read (ADR-014); otherwise "– (kein Zugriff)".
- Non-admin reports carry: "Admins sehen von dir nur diese Zahlen, keine Titel oder Inhalte."
- German copy (de.yaml) and English (en.yaml) for every new string.
- Docs in the same commit as the change (CHANGELOG under `[Unreleased]`, design.md rows, feature doc, ADR-015, arc42).

## Review Focus

1. An admin in scope *Alle* sees a title, file name or link of a page in a space they are no member of — must show "– (kein Zugriff)". (Task 3, 4, 6, 8 tests.)
2. Empty repository / repo with no HEAD / Git error — the page still renders, Git charts say "Historie gerade nicht lesbar" or show 0. (Task 2, 3 tests.)
3. A file deleted and re-added with the same content (same blob) counts as live, not as deleted. (Task 2 test.)
4. Concurrent first requests after a commit trigger one scan, not N. (Task 3 test with a counting scanner.)
5. Non-admin requesting `scope=all` gets 403; unknown tab 404; unknown scope falls back to the default. (Task 3 test.)

### Task 2: Git history scan

**Files:**
- Create: `internal/store/scan.go`, `internal/store/scan_test.go`

**Interfaces — Produces:**
```go
type FileChange struct {
	When        time.Time
	Name, Email string // commit author
	Path, Blob  string // Blob "" when deleted
	Size        int64  // bytes of Blob, 0 when deleted
	Deleted     bool
}
type Scan struct {
	Head      string        // "" for an empty repository
	Changes   []FileChange  // oldest first, renames as delete + add
	Live      map[string]int64 // path → size at HEAD
	Deleted   int64         // bytes of unique blobs reachable but not at HEAD
	DeletedN  int           // count of those blobs
	PackBytes int64         // `git count-objects -v`: size + size-pack, bytes
}
func (r *Repo) Head() (string, error)  // "" with nil error on an empty repo
func (r *Repo) Scan() (Scan, error)
```

- [ ] **Step 2:** `go test ./internal/store -run TestScan` — Expected: FAIL, `Scan` undefined.
- [ ] **Step 3: Implement.** `git log --reverse --no-renames --raw --no-abbrev --format=%x00%H%x09%ct%x09%ae%x09%an`; parse raw lines `:mode mode old new STATUS\tpath`. Deleted = unique blobs seen in Changes and not among HEAD blobs. Keep each function ≤ 30 lines (parseLog, blobSizes, liveFiles, countObjects).
