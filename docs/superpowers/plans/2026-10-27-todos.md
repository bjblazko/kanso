# Todo-Listen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shareable, offline-capable flat todo lists with one level of sub-items, stored as JSON files outside Git.

**Architecture:** New domain package `internal/todos` (store, operations, access) writing `todos/<id>.json`.
The web layer serves a JS-rendered page `/todos` (and `/todos/{id}`), a JSON snapshot/sync API, and
server-rendered owner pages for sharing and deleting. `web/static/js/todos.js` keeps a copy and an
operation outbox in IndexedDB (`kanso-todos`), the service worker serves the page offline.

**Tech Stack:** Go stdlib, `html/template`, plain JS modules, IndexedDB, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-27-todos-design.md`

## Global Constraints

- No new dependency; every new file starts with `SPDX-License-Identifier: Apache-2.0`.
- Functions ~30 lines, cyclomatic ≤ 10; packages by domain.
- No Git commits for todos; `/todos/` in the data directory's `.gitignore`.
- Admins have no extra access to todo lists.
- Limits: name ≤ 80 runes, item ≤ 500 runes, ≤ 1000 items per list, ≤ 500 ops per sync; tombstones older than 30 days are dropped.
- UI copy German and English (`internal/i18n/{de,en}.yaml`); rail entry "Todos"/"To-dos" between Notizen and Wiki.
- Checked items: stay in place, row with reduced opacity, no strike-through.
- Docs in the same commits: CHANGELOG, ADR-006, arc42 ch. 9 + building blocks, feature doc `docs/features/2026-10-27 todos.md`, README privacy, `docs/design.md` if a deviation arises.

## Review Focus

1. Ops for a list the person lost access to → rejected and acknowledged, never applied, client drops them.
2. Late `text`/`done` op for a deleted item → ignored (tombstone), item not revived.
3. `sub` on the first item or after deleting the main item → renders as a main item, never crashes.
4. Same op sent twice (lost answer) → same state; `add` with an existing id is a no-op.
5. Session expired while ops wait → ops stay in the outbox, status shows the sign-in link.

### Task 1: `internal/todos` – model, operations, store

**Files:**
- Create: `internal/todos/todos.go` (types, Store, Get/List/Create/Delete/Share, access, `.gitignore`)
- Create: `internal/todos/ops.go` (Op, Apply)
- Test: `internal/todos/todos_test.go`, `internal/todos/ops_test.go`

**Interfaces:**
- Produces:
  - `type Item struct { ID, Text string; Done, Sub bool; At Stamps }` with `Stamps struct{ Text, Done, Sub int64 }` (JSON `id,text,done,sub,at{text,done,sub}`)
  - `type Share struct { User, Group string }` (JSON `user,group`, omitempty)
  - `type List struct { ID, Name, Owner string; Shared []Share; Created, Updated time.Time; Items []Item; Deleted map[string]int64 }`
  - `type Op struct { ID, Kind, List, Item, After, Text string; Done, Sub bool; At int64 }`; kinds `create`, `rename`, `add`, `text`, `done`, `sub`, `delete`
  - `func NewStore(dataDir string, repo *store.Repo) (*Store, error)` (adds `/todos/` to `.gitignore`, commits it like notes)
  - `func (s *Store) Visible(sub string, g access.Groups) []List` – newest `Updated` first
  - `func (s *Store) Get(sub, id string, g access.Groups) (List, error)` – `ErrNotFound` if invisible
  - `func (s *Store) Apply(sub string, g access.Groups, ops []Op) []string` – returns ids of ops that were rejected
  - `func (s *Store) SetShares(owner, id string, shares []Share) error`, `func (s *Store) Delete(owner, id string) error` – `ErrNotFound` unless owner
  - `func Done(l List) (done, total int)`
  - errors `ErrNotFound`, `ErrBadID`

- [ ] **Step 1: Write failing tests** (`ops_test.go`, table-driven where natural):
