# Aufgaben (Boards) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Private and group task boards with Kanban and Eisenhower views, quick mobile capture that works offline, and note → task.

**Architecture:** New domain package `internal/tasks` stores `boards/<id>/board.yaml` and
`boards/<id>/tasks/<id>.md` in the Git-tracked data directory, one commit per change. Board, task and
admin pages are server-rendered (`html/template`); `web/static/js/board.js` adds drag and drop,
`web/static/js/task-capture.js` keeps an IndexedDB outbox for `/tasks/new`, which the service worker
serves offline. The task editor reuses `editor.js`.

**Tech Stack:** Go stdlib, `html/template`, plain JS modules, IndexedDB, native HTML drag and drop, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-30-tasks-design.md`

## Global Constraints

- No new dependency; every new file starts with `SPDX-License-Identifier: Apache-2.0`.
- Functions ~30 lines, cyclomatic ≤ 10; packages by domain (`huepattl-code-quality`); UI per `huepattl-rams-design` and `docs/design.md`.
- Statuses fixed: `open`, `doing`, `waiting`, `done` — "Offen · In Arbeit · Wartet · Erledigt" / "Open · Doing · Waiting · Done".
- Quadrants: urgent+important "Sofort", important "Planen", urgent "Kurz erledigen", neither "Später" (EN: "Do now", "Plan", "Do quickly", "Later").
- Limits: title ≤ 200 runes (required, not blank), body ≤ 100 KB, `waiting_for` ≤ 120 runes, ≤ 2000 tasks per board, board name ≤ 80 runes.
- Kanban "Erledigt" shows tasks with `done_at` within the last 14 days unless `?done=all`. Matrix never shows done tasks.
- Order in every column/quadrant: `due` ascending, tasks without `due` after, then `created` newest first.
- Private board: owner only; **admins get no access**. Group board: every member of the group, full edit rights. Invisible board or task → 404.
- Every change is one Git commit authored by the person (`users.User.Author()`), message `tasks: <title> → <what>`, inside `repo.Locked`.
- "Diese Woche" = coming Sunday (today if Sunday), computed on the device; overdue/heute/morgen on cards in server time (`time.Local`).
- Due date red = overdue, yellow = today/tomorrow, always with the word. "Speichern"/"Neue Aufgabe" are the only accent elements on their screens.
- Rail entry "Aufgaben"/"Tasks" between Todos and Wiki; `Module` "tasks".
- UI copy German and English in `internal/i18n/{de,en}.yaml`, keys `tasks.*`.
- HTTP tests live next to the handlers in `internal/web/*_test.go` (the project's existing place; there is no `internal/e2e`), browser tests in `e2e/tests/tasks.spec.js`.
- Docs in the same commits: CHANGELOG `[Unreleased]`, ADR-008, arc42, feature doc `docs/features/2026-10-26 tasks.md`, `docs/design.md`, README privacy.

## Review Focus

1. Outbox upload names a board that is gone or no longer visible → task lands on the person's own board, answer carries that board id, page says so once. (Task 1, Task 5)
2. Same task id uploaded twice (lost answer), even after the first copy was dragged or moved to another board → one task, second answer 200 with the existing board. (Task 1)
3. Drag or claim on a task someone else deleted or moved meanwhile → 404, no file recreated; the card snaps back with a hint. (Task 6)
4. Two first uploads of a person at once (private board does not exist yet) → exactly one private board. (Task 1)
5. Blank/over-long title or malformed `due` from the outbox → 400, item marked failed in the outbox, not retried forever. (Task 5)
